# Feature map

The menu-bar app uses the same controller and machine registry as the CLI. Click the shield icon or open `msi-screen://controls`. **Layout**, **Monitor**, **Machines** and **Peripherals** separate monitor layout, individual controls, saved computers and device diagnostics. Layout drafts require **Apply layout**; individual settings have their own **Apply** buttons. Machine routing buttons apply their explicit target directly. `python3 scripts/verify.py --gui --exercise` drives the layout surface with background Cua Driver actions, saves before/busy/after screenshots, and independently checks USB state through the CLI.

The 19 controls cover picture, color, motion/overlays, speaker volume and monitor OSD preferences. Availability depends on current mode and readable guard conditions. PIP editing, factory reset and monitor restart are not exposed. KVM switches the monitor hub between the configured USB-C Mac and USB-B Linux computer; directly paired Mac peripherals need Universal Control for Mac-to-Mac sharing. USB upstream must remain attached for monitor controls; per-Mac display roles use macOS APIs. UI automation requires Cua Driver permissions. Spaces uses the app’s separate Accessibility grant; receiver configuration and input testing have their own Input Monitoring requirements. Machine status failures remain visible rather than triggering automatic retries.

`python3 scripts/verify.py` health-checks the real CLI and checks locking, dry-run and input validation, including saved-machine route previews. `--exercise` also enables PBP, swaps sources, checks persistence from separate CLI processes, and restores the starting layout. `--exercise-controls` changes this Mac’s main display and brightness by one step, then restores only state it still owns; `--peer-host ALIAS` reads the companion's display state; `--gui --sharing` checks the optional helper.

`--exercise-machine ID` independently verifies full-screen, left and right machine targets and restores the full baseline after each only while exact layout ownership holds. With `--gui`, it drives that card's actual buttons. The baseline must have PIP off, distinct saved primary/secondary inputs, and matching PIP/PBP secondary inputs. These exercises prove readback and UI action/result paths, not the physical panel's picture.

Generic GUI polling checks wait 35 seconds for each 30-second timer interval plus tolerance, with ten-second progress checkpoints. Menu-bar unavailable/recovered screenshots need visual inspection: Cua desktop captures do not expose the status label, so the closed-panel polling verdict remains `INCONCLUSIVE` until reviewed.

A newly initialized USB-C video connection can require a second complete layout packet; that single bounded transition is detected through CoreGraphics and exact source readback. Run long verification through OMP. Evidence is kept in `.local/verify-*`; no monitor serial is collected.

`--gui --usb-route` inspects the visible Keyboard & mouse card, refreshes the read-only USB route, and compares the displayed USB-C / USB-B / Auto selection with independent `kvm status` reads. It never switches USB routing.

`--exercise-kvm ID` is separate from other exercises. Starting from USB-C with local control, it sends one USB-B request, verifies the new route and controller ownership, then returns once from an observed owned USB-B state. With `--gui`, it uses the Peripherals USB-B button and Machines USB-C button, checking the shared selector and capturing visible controls around each action. Add repeatable `--expect-usb VID:PID` options to require specific peripherals to newly enumerate on Linux and return to their baseline counts; without these options, peripheral enumeration is recorded without requiring a particular device. Upstream controller ownership requires a uniquely enumerated MSI controller and companion route readback. Final monitor video state must match the initial state. Ambiguous writes are followed by fresh status reads, never resent. If control ownership cannot be established, it reports the gap and skips local USB cleanup reads. USB enumeration does not verify mouse or keyboard events.

`--exercise-focus ID` uses independently predicted fullscreen targets and current-owner `kvm layout` reads to verify the combined Linux action and local Mac return. Only exact owned USB/layout pairs permit cleanup; the starting video layout is restored after USB-C ownership returns. Its GUI path temporarily enables Move USB with full screen, captures Layout fullscreen and PBP actions, verifies receivers remain on Linux after PBP, uses the Mac card to return, and restores that preference. Repeatable `--expect-usb VID:PID` selects optional USB devices to prove moved and returned.

`--peripherals` is a separate read-only owner-aware check and skips local HID-only preflight, so it also works while the controller is on Linux. It records raw topology, local game-controller identities and native profiles, local Rapoo descriptor/mouse detail results where available, and the recognized POP pairing's detail result or structured error. With `--gui`, it inspects both Machines and Peripherals, verifies the inline host selector matches the independent USB route and disables the current host, and captures available mouse/keyboard detail actions and results. Battery values may change between reads; field presence and valid ranges are checked without requiring equality. `--probe-pointer` additionally opts into a one-second CLI capture and ten-second GUI capture when enabled. `--probe-controller` does the same for native gamepad input and records an inconclusive result when no physical input arrives. Missing permission or remote ownership is recorded as skipped; the verifier does not change permission settings or require physical event counts. Inspect `peripheralDetails` / `peripheralDetailGUI` for unavailable reads or skipped probes even when the inspection itself passes. Offline verification rejects out-of-range mouse/controller probe durations, invalid receiver slots and unsupported mouse arguments before hardware access.
